# ORIGIN X — System Architecture and Experiment Plan

## 1. System Vision & Purpose
ORIGIN X is a probabilistic classification and verification platform designed to estimate whether an image was created by a human or generated by artificial intelligence.

> **Foundational Principle:** ORIGIN X treats origin estimation as a probabilistic classification task under epistemic uncertainty. It provides a calibrated statistical probability estimate and confidence interval rather than claiming forensic proof or certainty.

### Prediction Labels
1. `HUMAN_CREATED` (Class 0): Photographs (camera sensor optics, smartphone, DSLR), traditional physical artwork (oil, watercolor, acrylic, sketching), and human-authored digital illustration/vector art.
2. `AI_GENERATED` (Class 1): Imagery synthesized by generative models (latent diffusion, autoregressive, flow-matching, GANs, and neural rendering).
3. `INCONCLUSIVE`: An explicit abstention state triggered when model confidence is low, calibration uncertainty is high, or when the image is out of distribution.

### Intended Users
- Digital art platforms, content moderators, archivists, researchers, and creators seeking non-punitive, probabilistic transparency regarding image origin.

### Supported Inputs and Constraints
- **Formats:** JPEG (`.jpg`, `.jpeg`), PNG (`.png`), WebP (`.webp`).
- **File Size Limit:** 15 MB max payload.
- **Dimensional Bounds:** Min 64x64 px; Max 8192x8192 px.
- **Color Profiles:** sRGB (CMYK, palette, and alpha channels are safely normalized and composited).

### Out-of-Scope Cases
- Compressed video frames, animated GIFs/APNG.
- Microscopic, astronomical, or medical radiology (X-ray, MRI, CT) sensor data.
- Complex hybrid composites (e.g., human photograph with 5% AI inpainting) without localized pixel segmentation.
- Forensic courtroom evidence.

## 3. Four-Phase Experimentation Plan

1. **Phase 1 — Audit, Define, & Prepare Data:**
   - Establish benchmark collections across varied human creators and AI generator families.
   - Enforce source-level split isolation (Train, Val, Test, Untouched Evaluation).
   - Establish 22-dimensional statistical baseline.
   - Record shortcut learning vulnerabilities and baseline metrics.

2. **Phase 2 — Train & Compare Models (including ANNs):**
   - Implement deep Convolutional Neural Network (ANN) and Transfer Learning architectures.
   - Implement temperature-scaled calibration and Platt scaling.
   - Evaluate against held-out test set and untouched evaluation set.
   - Run robustness stress tests (JPEG compression Q=50/75/90, blur, resize) and shortcut ablations.

3. **Phase 3 — Build the Web Product:**
   - Develop responsive FastAPI backend with strict memory sanitization.
   - Implement Apple Design and Apple Motion standards (system fonts, fluid springs, dark/light mode, reduced motion support).
   - Design transparent probabilistic UI with confidence ranges and inconclusive handling.

4. **Phase 4 — Quality, Hardening, & Release Readiness:**
   - Automated regression test suite (unit, integration, edge cases).
   - Security audit (zero-retention, header validation, memory release).
   - Model cards, documentation, and release verification.
